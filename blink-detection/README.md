
# blink-detector：基于计算机视觉的实时眨眼检测工具

`blink-detector` 是一个轻量级、高精度的实时眨眼检测工具。它结合了 `dlib` 面部关键点检测与 `OpenCV` 视频处理能力，通过计算眼睛纵横比（EAR, Eye Aspect Ratio）来精准识别闭眼动作并统计眨眼次数。

**功能亮点：**
- 实时检测：支持本地视频文件及摄像头视频流的实时分析。
- 科学算法：采用 EAR 算法，计算高效且对头部姿态具有一定的鲁棒性。
- 双眼协同：支持左右眼独立检测并取平均值，有效减少单眼遮挡造成的误判。
- 灵活配置：核心阈值参数支持自定义调整，适应不同光照与视频质量。
- 实时可视化：在视频流中动态绘制眼睛轮廓，并实时显示 EAR 值与眨眼计数。

---

## 功能特性

- **实时视频流眨眼检测**：逐帧分析视频画面，低延迟反馈检测结果。
- **基于 EAR（眼睛纵横比）算法**：通过几何特征量化眼睛的开合程度，避免复杂的深度学习推理开销。
- **左右眼联合判定**：分别计算左右眼的 EAR 并取平均，提升检测的稳定性。
- **可配置阈值参数**：提供 EAR 阈值与连续帧数阈值，方便根据实际场景微调。
- **丰富的实时可视化**：
  - 绘制眼睛区域的绿色凸包轮廓。
  - 画面左上角实时显示当前眨眼总次数。
  - 画面左上角实时显示当前帧的 EAR 数值。

## 安装步骤

### 1. 安装 Python 依赖
在项目根目录下执行以下命令安装所需的第三方库：

```
pip install scipy numpy dlib opencv-python
```

### 2. 获取 dlib 预训练模型
本项目依赖 dlib 的 68 点面部关键点预测模型。请通过以下方式获取：
1. 前往 dlib 官方模型库或相关开源资源站下载 `shape_predictor_68_face_landmarks.dat.bz2`。
2. 解压 `.bz2` 文件，得到 `shape_predictor_68_face_landmarks.dat`。
3. 将该文件放置在项目目录下，或记录其绝对路径以便在运行时指定。

## 使用方法

项目入口文件为 `detect_blinks.py`。

**基本运行示例（检测视频文件）：**

```
python detect_blinks.py -p shape_predictor_68_face_landmarks.dat -v path/to/your/video.mp4
```

**不指定视频文件（默认调用系统摄像头）：**

```
python detect_blinks.py -p shape_predictor_68_face_landmarks.dat
```

**操作提示：** 在视频播放窗口中，按 `ESC` 键可随时退出程序。

## 工作原理

### EAR 算法原理

眼睛纵横比（Eye Aspect Ratio, EAR）通过计算眼部 6 个关键点之间的欧氏距离来衡量眼睛的开合程度。

计算公式为：`EAR = (A + B) / (2.0 * C)`

- `A` 和 `B` 为上下眼睑之间的垂直距离。
- `C` 为左右眼角之间的水平距离。

当眼睛睁开时，EAR 值保持相对稳定；当眼睛闭合时，垂直距离急剧减小，导致 EAR 值显著下降。

### 眨眼判定逻辑

为了防止因单帧噪声或瞬间遮挡导致的误判，程序采用了**阈值 + 连续帧数防抖**机制：

1. **阈值判定**：当计算出的平均 EAR 值低于设定阈值（默认 `0.3`）时，系统认为当前帧为闭眼状态。
2. **连续帧确认**：只有当连续闭眼帧数达到设定阈值（默认 `3` 帧）时，才将此次动作计为一次有效眨眼，并将眨眼总数加 1。

## 注意事项

- **模型路径**：请务必确保 `-p` 参数传入的模型文件路径正确且文件存在，否则程序将无法启动。
- **环境影响**：视频分辨率、画面清晰度以及环境光照条件会直接影响人脸检测和关键点提取的精度，进而影响 EAR 的计算。
- **参数调优**：默认的 EAR 阈值（`EYE_AR_THRESH = 0.3`）和连续帧数（`EYE_AR_CONSEC_FRAMES = 3`）适用于多数常规场景。若在实际应用中出现漏检或误检，建议根据具体视频源的特性对这两个参数进行微调。
